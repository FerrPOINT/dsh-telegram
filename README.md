# DSH Telegram

[English](README.en.md)

Форк [IgnatAi401/dsh-telegram](https://github.com/IgnatAi401/dsh-telegram) для обычного общения с DSH в личном Telegram-чате. Плагин работает внутри Cordis, использует Session Controller и штатное хранилище DSH. Отдельного gateway или runner нет.

Версия 0.5.0 рассчитана на DSH **0.2.2-rc.5** и Node **24.9+**.

## Установка и настройка

Установите плагин штатной командой, указав проверенный commit:

```sh
dsh plugin --profile web add github:FerrPOINT/dsh-telegram#<commit>
```

Профиль должен предоставлять `sessionController`, `workspaceRegistry`, `storageDomain`, модель и стандартный agent preset. Создайте workspace в DSH и задайте его абсолютный путь в профиле:

```yaml
- id: telegram
  config:
    workspacePath: /opt/dev
    preset: standard
```

Токен и список разрешённых пользователей задаются в настройках плагина или в защищённой конфигурации профиля. Не публикуйте токен. Поддерживаются только личные чаты; не запускайте два poller с одним токеном.

## Разговоры

Просто отправьте сообщение, изображение или файл. Первый ввод создаёт разговор в настроенной папке. Следующие сообщения продолжают его, в том числе после перезапуска DSH и изменения токена того же бота. Каждый разрешённый приватный чат имеет собственную привязку.

- `/new` — начать разговор с чистым контекстом, сохранив прежнюю историю.
- `/sessions` — список разговоров; `/sessions 2` показывает следующую страницу.
- `/resume ID` — продолжить сохранённый разговор в выбранной рабочей папке.
- `/stats`, `/compact`, `/resend` — статистика, сжатие контекста и повтор ответа.
- `/help` — справка.

`/menu` остаётся необязательным расширенным управлением моделями и рабочими папками. Основному чату и текстовым командам выбора разговора не нужны widget-меню. Расширенные панели исходного плагина, вопросы и разрешения используют Telegram widgets.

## Хранение и ошибки

Привязки принадлежат домену DSH `telegram_chats`, версия 1, таблица `chats`. Ключ — `<bot-id>_<private-chat-id>`, поля — `workspaceId` и `sessionId`; `null` вместо sessionId означает отсутствие активного разговора после архивации. История сообщений остаётся в обычных журналах DSH. Токен и временное состояние панелей в домен не записываются.

Выбор нового разговора сохраняется до замены активной привязки. Остановка плагина не удаляет выбор. При восстановлении учитывается действующий allowlist. Недоступная сохранённая сессия вызывает явную ошибку; плагин не подставляет другой разговор. `/new` создаёт новый по явному запросу, сохраняя старые данные.

## Обновление с 0.4

`workspacePath` теперь обязателен. В 0.4 выбор существовал только в памяти, поэтому автоматически переносить было нечего. Если нужно продолжить конкретный старый разговор, перенесите известные workspace/session ID в домен `telegram_chats` перед запуском либо используйте `/sessions` и `/resume` после установки. Для JSON backend домен находится в `<DSH_HOME>/storages/telegram_chats.json`; используйте текущий формат storage-domain и не перезаписывайте существующие записи.

## Проверки

```sh
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm run build
```

Интеграционная проверка запускает настоящий DSH с плагином; подменяются только внешние API Telegram и модели. Проверяются обычное первое сообщение, сохранение выбора после перезапуска, разделение контекста через `/new`, возврат `/resume`, allowlist, typing и отсутствие обязательного widget-меню.
